# RozkladX — розклад КАІ ТЕХ

Статичний сайт на GitHub Pages: https://rozkladx.github.io/ — без власного сервера; дані у файлах data/*.json і (за бажанням) у базі Supabase.

## Звідки дані
| Що | Джерело | Як оновлюється |
|---|---|---|
| Розклади всіх груп | PDF на сторінці «Розклад занять» сайту коледжу | GitHub Actions щодня розбирає PDF → `data/schedules.json` |
| Заміни, розпорядження, робочі суботи | «Заміни.xlsx» на Google Drive коледжу | сайт читає напряму кожні 10 хв; Actions кожні 30 хв веде архів у `data/orders.json` |
| Повітряні тривоги | `ubilling.net.ua/aerialalerts` через `r.jina.ai` | сайт опитує кожні 30 с |
| Посилання на онлайн-пари | `js/data.js` → `links.lessons` | вручну (у PDF їх немає) |

## Розклад викладача
У вікні вибору групи після курсів є вкладка **«Викладачі»** (пошук теж знаходить прізвища).
Окремих розкладів викладачів коледж не публікує — сайт збирає їх із розкладів усіх груп
(`data/schedules.json` або база). Кілька груп в одну пару показуються разом. Робочі суботи
рахуються за курсом кожної групи. Заміни в сітку викладача не накладаються — у розпорядженнях
підсвічуються рядки, де він є (за прізвищем).

## Доступ «Викладач» (усе бачить, нічого не змінює)
`supabase/teachers.sql` додає роль `teacher`. Адмін у кабінеті → «👥 Акаунти» → **«🧑‍🏫 Посилання для викладачів»**
копіює посилання `…/#teach=код` і надсилає його. Хто відкриє й зареєструється (або ввійде акаунтом, що ще
чекає підтвердження), одразу стає викладачем: бачить посилання на пари, посилання для студентів і правки
всіх груп та список акаунтів. Змінювати нічого не може — у базі в нього лише права читання.
«Нове посилання» робить старе недійсним; забрати доступ — змінити роль або видалити акаунт.
Адмін і староста, які відкриють посилання, свою роль не втрачають; відхилені адміном доступ не отримують.

## База: розклади й заміни з історією
`supabase/history.sql` — таблиці `schedule_groups`, `schedule_versions` (кожна нова версія розкладу
групи, старі не видаляються), вид `schedule_current` і `order_archive` (усі розпорядження без ліміту 80).
1. Supabase → SQL Editor → виконати `supabase/schema.sql` (якщо база нова), потім `supabase/history.sql`.
2. GitHub → Settings → Secrets and variables → Actions → секрет `SUPABASE_SERVICE_ROLE_KEY`
   (Supabase → Settings → API → `service_role`). Його бачить лише робот, на сайт він не потрапляє.
3. У `js/data.js`: `supabase.url`/`anonKey` — ваш проєкт, `dataSource: 'db'`.

Робот і далі пише `data/*.json`, тож якщо база недоступна, сайт бере файли.

## Як додати посилання на пари
У `js/data.js` → `links.lessons` додайте групу (назва як у списку на сайті, напр. `'К-33, К-30'`)
і пари `'Прізвище викладача': 'посилання'`. Якщо в одного викладача різні посилання на різні предмети —
ключ `'Прізвище|Початок назви предмета'`.

## Робот оновлення
`.github/workflows/update-data.yml` запускає `tools/build-data.mjs`:
- `node tools/build-data.mjs` — розклади + архів замін;
- `node tools/build-data.mjs --only-orders` — лише архів замін.

Запустити вручну: вкладка **Actions** → «Оновлення розкладів і замін» → **Run workflow**.
Якщо PDF якоїсь групи не вдалося прочитати, лишається попередня версія, а на сайті з'являється попередження.

## Що вміє сайт
- вибір групи, розклад на день і тиждень, поточна/наступна пара з таймером;
- робочі суботи (по колу ПН I → … → ПТ II, окремо для 1 курсу та 2–4 курсів; розпорядження мають пріоритет);
- час у поясі пристрою; тривоги зі звуком і сповіщеннями; 6 стилів, у кожного свої звуки; мікшер.

## Оновлення файлів сайту
Після змін у css/js збільште версію в `index.html` (тег `app-version` і `?v=` біля файлів) — інакше браузери
можуть узяти старі файли з кешу. Відкриті вкладки самі перезавантажаться протягом 5 хв.
